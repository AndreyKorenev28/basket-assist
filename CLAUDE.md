# CLAUDE.md — basket-assist

## Что это за проект
Ассистент для игроков любительской баскетбольной команды (Россия, один или несколько любительских чемпионатов).
Три основные задачи сервиса:
1. **Расписание** — когда, где и с кем следующая игра.
2. **Скаутинг соперника** — базовая статистика команды соперника (результаты, место в таблице, лидеры).
3. **Сбор состава** — опрос игроков «буду / не буду» и передача капитану готовой заявки на игру (номер + ФИО) с проверкой каждого игрока по заявке на сезон с сайта лиги.

**Целевое решение:** для любой команды, бесплатно (монетизация, возможно, позже), канал на выбор — Telegram, VK или Max. **MVP:** только наша команда, канал **VK** ([ADR 0003](docs/decisions/0003-mvp-channel-vk-return.md); короткий переход на Telegram — ADR 0002, отменён). Telegram и Max — после MVP.

Стадия: **разработка MVP** — этапы M0–M4 готовы (бот работает в тестовой беседе), далее M5 (VPS) и M6 (пилот). Подробности — в `docs/vision.md`, план — `docs/architecture.md`.

**Это выпускная работа владельца на курсе по Claude Code.** Описание для защиты — `docs/course-project.md`. После завершения MVP проект демонстрируется на защите. При существенных изменениях (функции, стек, статус) обновлять и этот файл. Процесс работы с Claude Code (инструкции, субагенты, ADR, тесты) — тоже часть результата, его стоит делать наглядным.

## Правила работы
- Отвечать на русском. Для нетривиальных задач — сначала короткий план, потом выполнение.
- **Не выдумывать факты о лигах и их сайтах.** Структуру сайтов, API, форматы данных — только после реальной проверки (WebFetch / браузер). Непроверенное помечать «⚠ не проверено».
- Каждое существенное решение (стек, канал, источник данных, хранение) — оформлять ADR в `docs/decisions/` по шаблону из `docs/decisions/README.md`. Принятые решения не пересматривать без явного запроса.
- Новые вопросы, которые может решить только пользователь, — добавлять в `docs/open-questions.md`, а не угадывать ответ. Закрытый вопрос — переносить в раздел «Решено» со ссылкой на ADR.
- Термины (матч, заявка, состав, ростер, отметка участия и т. п.) — как в `docs/domain.md`. Новый термин — сначала добавить туда.
- **Коммиты:** по завершении каждого этапа (M0, M1, …) — без отдельного вопроса (разрешение владельца 2026-10-18). `git push` и публикация на GitHub — только с подтверждения. Секреты (токены ботов, ключи) — только в `.env`, никогда в коде и документах.
- Python — только в venv проекта (`py -m venv .venv`, `python -m pip install ...`), см. глобальный CLAUDE.md.
- Обновлять раздел «Текущий статус» ниже по мере продвижения.

## Ограничения предметной области
- **Персональные данные (152-ФЗ).** ФИО, даты рождения, номера, ID в мессенджерах — персональные данные. В целевом решении (для любых команд) сервис становится оператором ПДн: нужна политика обработки и согласие при подключении. Собирать минимум, хранить данные граждан РФ на серверах в РФ, иметь согласие и возможность удаления. Учитывать при выборе хостинга.
- **Источники данных ненадёжны.** Сайты любительских лиг меняют вёрстку, расписание переносят, протоколы публикуют с задержкой. Парсеры должны падать громко, а у капитана должен быть ручной ввод/исправление.
- **Пользователи — не айтишники.** Минимум действий: отметиться на игру — в один тап. Никаких регистраций ради регистрации.
- **Лиги заранее не известны.** В целевом решении капитан подключает лигу и команду сам, по ссылкам. Поэтому данные читаются через адаптеры платформ (`docs/data-sources.md`), а не через код под конкретную лигу. В MVP ссылки задаются в конфигурации (их передаст владелец проекта), но интерфейс адаптера сохраняется.
- **Мультитенантность с первого дня.** Целевое решение — для любой команды. В MVP команда одна, но все пользовательские данные привязаны к `tenant_id`, и запросы всегда фильтруются по нему.
- **Права капитана** (сводки, правка заявки на игру, сопоставление с заявками на сезон) есть у капитана, заместителя и временного **и. о. капитана**, которого они назначают из сопоставленных игроков. Везде, где в документах сказано «капитан получает/может», имеется в виду любой из них (`domain.md`, «Права капитана и их передача»).
- **Одна команда — разные названия в разных лигах.** Наш коллектив (команда сервиса) в каждой лиге выступает под своим названием и со своей заявкой на сезон: «Westchester» в АБЛ, «МИРЭА» в МЛБЛ. Проверка игрока, его номер и привязка к заявке на сезон — всегда в рамках конкретного выступления (`TeamEntry`), см. `domain.md`.
- **Мессенджер не зависит от логики.** Telegram, VK, а позже Max подключаются через `ChannelAdapter`. В бизнес-логике нельзя ничего специфичного для конкретного мессенджера. Функции, которые есть не везде, должны иметь запасной вариант.
- **Заявка на сезон и заявка на игру — разные вещи** (см. `domain.md`). Без уточнения слово «заявка» не используется. В заявку на игру попадают только игроки, которые есть в заявке на сезон. Если игрока там нет, об этом обязательно сообщается и капитану, и игроку.
- **Ритм расписания.** Игры почти всегда по выходным. Лиги публикуют расписание по-разному: в АБЛ матч появляется во вторник сразу с временем, в МЛБЛ весь круг известен заранее. **Опрос запускается в среду перед игрой, если время известно** (или сразу, когда время появилось позже). **Без времени опрос не запускается**, капитан получает предупреждение и связывается с лигой. См. `domain.md`. Последнее слово в заявке на игру за капитаном: он может добавить не ответивших и убрать лишних. Капитан подаёт заявку на игру сам, прямо перед игрой. Сервис присылает ему сводки **за 24 ч и за 2 ч** до игры. В заявке на игру **от 5 до 12 игроков** (настройка лиги).
- Время матчей — с часовым поясом лиги (по умолчанию Europe/Moscow), хранить в UTC.

## Хостинг
**RUVDS START HIT SSD** (1 ядро / 1 ГБ / 20 ГБ, Debian 13; FirstVDS из ADR 0001 — нет в наличии), VPS в российском дата-центре, **минимальный бюджет**. Развёртывание и эксплуатация — `deploy/README.md`; бот на компьютере разработчика больше не запускать (два бота делят события Long Poll). Поручения на обработку ПДн у провайдера нет: согласие игроков и минимум ПДн обязательны, перед целевым решением провайдера пересмотреть. Проектировать под самый маленький тариф: один процесс, SQLite в MVP, никаких платных внешних сервисов, обязательно предусмотреть бэкап БД. Каждую новую зависимость оценивать по потреблению памяти. Сайты лиг опрашивать экономно, с кэшированием.

## VK (канал MVP)
Сообщество «Basket Assist» (club242389357). Бот — только от имени сообщества, работает в беседе команды и в личке. События — Bots Long Poll. Опрос — анонс-голосование «Буду / Не буду» с именами под каждым вариантом, обновляется до финальной заявки (ADR 0004). Бот — **администратор беседы**, но обрабатывает только обращения к себе и свои кнопки; прочие сообщения не обрабатываются и не сохраняются. В личку бот пишет только тем, кто сам нажал «Начать» (`vk.me/club<ID>?ref=…`, проверено). **Бота в беседу приглашает участник, не являющийся админом сообщества** — у админа кнопки нет (ADR 0003). Используем только документированные методы VK. Риски: месячный лимит вызовов VK ID, возможный переезд бесед в MAX (ошибка 993). Подробности — `docs/data-sources.md`, `spikes/vk-probe/README.md`.

## Команды
Все — из корня проекта, в venv `.venv` (PowerShell: `.venv\Scripts\Activate.ps1`; Git Bash: `.venv/Scripts/python`).
- Установка: `py -3.13 -m venv .venv` → `python -m pip install -e ".[dev]"`
- Тесты: `python -m pytest -q -n auto` (параллельно, ~20–30 с; без `-n auto` — ~1,5 мин)
- Линтер и формат: `python -m ruff check src tests scripts` и `python -m ruff format src tests scripts`
- Проверка конфига и БД: `python -m basket_assist --check`
- Синхронизация с лигами и просмотр: `python -m basket_assist --sync --show`
- Запуск бота: `python -m basket_assist`; анонс вручную (до M4): `python -m basket_assist --post-poll ID`
- Импорт участников беседы и подтверждений сопоставления: `python -m basket_assist --import-chat` (файлы `data/team_chat_members.json`, `data/matching_confirmed.json`); черновик — `python scripts/draft_matching.py`
- Обновить фикстуры API лиг (обезличенные): `python scripts/capture_fixtures.py`
- **Сервер (VPS):** выкладка — `sh deploy/deploy.sh` (только закоммиченное; секреты/база — флаги `--with-secrets`, `--with-db`, см. `deploy/README.md`); логи — `ssh -i ~/.ssh/basket_assist_vps $(cat deploy/host.local) journalctl -u basket-assist -f`; копия базы себе — «Забрать бэкап.cmd» (двойной щелчок) или `sh deploy/fetch-backup.sh`.
- Новая миграция после изменения `storage/tables.py`: см. `tests/test_storage.py::test_migrations_match_models` — тест падает, если миграция не создана.

Локальные файлы вне git: `.env` (секреты), `config/tenant.toml` (команда, VK ID, беседа), `data/` (БД, бэкапы, черновики сопоставления), `deploy/host.local` (адрес сервера); SSH-ключ сервера — `~/.ssh/basket_assist_vps`. Вывод кириллицы в консоли Windows может отображаться кракозябрами — это кодировка терминала (`PYTHONIOENCODING=utf-8` помогает).
