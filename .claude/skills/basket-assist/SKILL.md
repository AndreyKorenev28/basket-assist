# Basket Assist — типовые операции

Проект: Python 3.13, один asyncio-процесс (бот VK + планировщик + синхронизация с лигами), SQLite. Код — `src/basket_assist/`,
описание — `CLAUDE.md`, домен и термины — `docs/domain.md`, архитектура — `docs/architecture.md`, решения — `docs/decisions/`.

## Правила (всегда)

- **Python — только из venv проекта:** Git Bash — `.venv/Scripts/python`, PowerShell — `.venv\Scripts\python`. Команды `python3` в Windows нет.
- **Один бот на сообщество.** Бот работает на сервере. Не запускай `python -m basket_assist` (без флагов) на компьютере разработчика: два процесса делят события Long Poll, и часть нажатий теряется. Флаги `--check`, `--sync --show` на локальной базе — можно.
- **Секреты** (токен VK, адрес сервера) — только в `.env`, `deploy/host.local`; команда, беседа и VK ID руководителей — в `config/tenant.toml`. Эти файлы вне git, не выводи их содержимое в чат.
- **Персональные данные (152-ФЗ).** В коде, тестах, документах и коммитах — только вымышленные имена. Реальные ФИО и VK ID игроков — только в базе и локальной конфигурации. Временные выгрузки с именами — в scratchpad, после проверки удалить.
- **Перед коммитом:** `python -m ruff check src tests scripts`, `python -m ruff format src tests scripts`, `python -m pytest -q -n auto` (~25 с). Изменил `storage/tables.py` — нужна миграция Alembic (тест `test_migrations_match_models` упадёт без неё).
- **Документы как источник истины.** Существенное решение — ADR в `docs/decisions/`, новый термин — сначала в `docs/domain.md`, вопрос для владельца — в `docs/open-questions.md`.
- **Необратимые действия** (удаление сообщений в беседе команды, массовые рассылки, удаление данных из базы, `--with-db`) — только с явного согласия владельца; перед изменением базы на сервере — бэкап.
