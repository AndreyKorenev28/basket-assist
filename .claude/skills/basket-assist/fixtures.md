# Обновление образцов ответов API лиг

Контрактные тесты адаптеров (`tests/test_sources.py`) работают на сохранённых ответах API лиг в `tests/fixtures/<платформа>/`.
Сеть в тестах не используется (HTTP мокается через `respx`).

## Когда обновлять
- адаптер упал на живых данных (ошибка разбора в логе синхронизации) — лига поменяла формат;
- новый сезон / турнир (поменялись ID в `config/tenant.toml`);
- добавлен новый запрос в адаптер.

## Порядок
1. `.venv/Scripts/python scripts/capture_fixtures.py` — скачивает ответы (список URL — `REQUESTS` в скрипте; при новом
   турнире поправить ID там же) и **обезличивает**: ФИО, даты рождения, фото, контакты → заглушки; названия команд и залов
   сохраняются.
2. **Проверить обезличивание до коммита** — в `tests/fixtures/` не должно остаться реальных ФИО и дат рождения:
   ФИО — заглушки вида `last12`/`first12`, даты рождения — `2000-01-01`. Сверка с реальными фамилиями из локальной базы:
   ```
   for n in $(.venv/Scripts/python -c "import sqlite3;c=sqlite3.connect('data/basket_assist.db');print(' '.join({r[0] for r in c.execute('select last_name from season_roster_entry')}))"); do grep -rlw "$n" tests/fixtures; done
   ```
   Вывод должен быть пустым. Если что-то нашлось — дополнить список ключей с ПДн в скрипте и запустить заново.
3. `git diff --stat tests/fixtures` — посмотреть, что поменялось; большие неожиданные изменения структуры = изменился формат API.
4. `.venv/Scripts/python -m pytest -q tests/test_sources.py`. Упало из-за нового формата — поправить адаптер
   (`src/basket_assist/sources/<платформа>.py`) и тесты, затем полный прогон `-m pytest -q -n auto`.
5. Если формат изменился существенно — отметить в `docs/data-sources.md` (что поменялось и когда).
