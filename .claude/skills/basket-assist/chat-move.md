# Переезд бота в другую беседу

У команды одна **активная беседа** на мессенджер (`chat.active`) — та, что указана в `vk_chat_peer_id` в `config/tenant.toml`.
После смены peer_id прежняя беседа гаснет: бот там не отвечает (на упоминание — «переехал», на кнопки — «Голосование
перенесено»), а открытые анонсы планировщик в течение минуты публикует заново в новой беседе и закрепляет (`polls.relocate`;
общий анонс — одним сообщением). Отметки привязаны к матчу и переезжают вместе с анонсом. Полный порядок —
`deploy/README.md`, раздел «Переезд беседы».

## Перед переездом
- В новой беседе бот должен быть **администратором** (закрепление, список участников). Пригласить бота может участник,
  **не являющийся** админом сообщества (ADR 0003).
- peer_id беседы = 2000000000 + номер беседы у сообщества. Название и права бота можно проверить
  `messages.getConversationsById` (ключ сообщества из `.env`, только чтение).
- Уточни у владельца, что делать с закреплённым сообщением в новой беседе: в VK закреплено одно сообщение, анонс бота его
  заменит (прежнее открепится, не удалится).
- Тестовые отметки: если они есть, спросить владельца, удалять ли.

## Порядок
1. Код с переездом уже на сервере (иначе `sh deploy/deploy.sh`).
2. На сервере: `systemctl stop basket-assist && systemctl start basket-assist-backup`; при согласии владельца удалить
   тестовые отметки будущих матчей (SQL — в `deploy/README.md`).
3. Локально: `vk_chat_peer_id = <новый peer_id>` в `config/tenant.toml` → `sh deploy/deploy.sh --with-secrets` (бот запустится).
4. Проверить: в логе `анонс матча N перенесён из беседы A в B`; через API — закреплено сообщение бота с кнопками,
   в старой беседе анонс заменён текстом «Анонс перенесён…» без кнопок.

## Откат
Вернуть прежний `vk_chat_peer_id` и снова `sh deploy/deploy.sh --with-secrets` — анонсы переедут обратно тем же механизмом.
