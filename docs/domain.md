# Доменная модель и глоссарий

Термины ниже — единственные допустимые в коде, документах и интерфейсе. Новый термин сначала добавляется сюда.

## Глоссарий
| Термин | Определение | В коде |
|---|---|---|
| Лига | Организатор чемпионатов (сайт, регламент). В MVP: АБЛ (ablforpeople.com), МЛБЛ (moscow.ilovebasket.ru) | `League` |
| Источник | Ссылка на страницу лиги/турнира/команды и платформа сайта, через которую читаются данные | `Source` (`url`, `platform`, `external_id`) |
| Адаптер платформы | Модуль, который читает данные с сайтов одной платформы и приводит их к доменной модели | `PlatformAdapter` |
| Турнир / сезон | Конкретный чемпионат лиги за сезон, может иметь дивизионы, группы, плей-офф | `Tournament` |
| Команда сервиса | Наш коллектив, подключённый к сервису: один набор игроков, капитан, канал, настройки. Все пользовательские данные изолированы по ней | `Tenant` → `tenant_id` |
| Команда в лиге | Команда в том виде, как её знает конкретная лига: своё название, свой ID на сайте лиги, своя заявка на сезон. Это может быть наша команда или соперник | `LeagueTeam` (`league_id`, `external_id`, `name`) |
| Выступление | Связь команды сервиса с командой в лиге в конкретном турнире. У одной команды сервиса может быть несколько выступлений с разными названиями (пример: «Westchester» в АБЛ, «МИРЭА» в МЛБЛ) | `TeamEntry` (`tenant_id`, `league_team_id`, `tournament_id`) |
| Игрок | Член нашего коллектива (человек), один на все лиги и турниры | `Player` |
| Роль | Права игрока в команде сервиса: `player`, `captain`, `vice_captain`. Капитан и заместитель получают сводки, правят заявку на игру и сопоставляют игроков. В MVP капитан и заместитель задаются в `config/tenant.toml` (вне git) | `Player.role` |
| Исполняющий обязанности капитана (и. о.) | Сопоставленный игрок, которому капитан или заместитель временно передал **все права капитана** — например, когда оба в отпуске | `PermissionGrant` (`permission` = `acting_captain`, `granted_by`, `valid_until`, `revoked_at`) |
| Руководитель команды | Капитан, заместитель или действующий и. о. капитана — все, у кого есть права капитана | — |
| Аккаунт в мессенджере | Привязка игрока к пользователю VK / Telegram / Max | `MessengerAccount` (`channel`, `external_user_id`) |
| Канал | Мессенджер, через который команда работает с сервисом: `telegram`, `vk`, `max` | `Channel`, `ChannelAdapter` |
| **Заявка на сезон** | Список игроков, зарегистрированных лигой за команду в лиге в турнире; у каждого выступления своя. Берётся с сайта лиги. Поля: ФИО, номер; дополнительно, если есть: дата рождения, позиция | `SeasonRoster` / `SeasonRosterEntry` |
| Матч | Игра двух команд в турнире: дата, время (может быть ещё не назначено), зал, статус, счёт | `Match` (`match_date`, `start_at`, `time_status`) |
| Хозяин и гость | Порядок команд в календаре лиги: хозяин слева, гость справа. Бот везде показывает матч в этом порядке, как на сайте лиги. Проверено: в АБЛ хозяин — `team` в API MTGame, в МЛБЛ — `TeamA` в Infobasket, на сайтах они слева | `Match.home_team_id` / `away_team_id` |
| Цвет формы | Хозяин (слева в календаре) играет в светлой форме, гость (справа) — в тёмной. Для АБЛ это регламент, п. 10.3. Для МЛБЛ правило назвал владелец, по регламенту ⚠ не проверено. Бот пишет «👕 Наша форма: светлая/тёмная» в «Играх», анонсе и «составе» | `schedule.kit_hint` |
| Зал | Место проведения: название, адрес, ссылка на карту | `Venue` |
| Отметка участия | Ответ игрока на конкретный матч: `going` / `not_going` / нет ответа (варианта «под вопросом» нет — решение владельца) | `Attendance` |
| Состав на матч | Игроки, подтвердившие участие (на текущий момент). Руководитель видит его по команде «состав»: игроки без заявки на сезон в этой лиге показаны с ⚠️ и в заявку на игру не идут | `MatchLineup` |
| **Заявка на игру** | Список «номер + ФИО» для лиги на конкретный матч. Основа — состав на матч, капитан может добавлять (в т. ч. не ответивших на опрос) и убирать игроков | `MatchApplication` / `MatchApplicationEntry` (`source`: `poll` / `added_by_captain`) |
| Подача заявки на игру | Капитан подаёт заявку на игру непосредственно перед игрой. Для сервиса «дедлайн» = время начала матча (`start_at`) | — |
| Сводка капитану | Сообщение капитану с черновиком заявки на игру и статусом опроса. Отправляется за 24 ч и за 2 ч до игры | `CaptainDigest` (`kind`: `t_minus_24h` / `t_minus_2h`) |
| Справка по сопернику | Сводка статистики соперника перед матчем | `OpponentReport` |

> «Заявка» без уточнения не используется: всегда «заявка на сезон» или «заявка на игру».

## Сущности и связи
```
Tenant (команда сервиса) 1─* Player, 1─1 Channel-настройка
Tenant 1─* TeamEntry *─1 LeagueTeam *─1 League      (Westchester@АБЛ, МИРЭА@МЛБЛ)
TeamEntry *─1 Tournament, 1─* Source
League 1─* Tournament 1─* Match *─1 Venue
Match: home, away → LeagueTeam
TeamEntry 1─1 SeasonRoster 1─* SeasonRosterEntry
Player 0..1─* SeasonRosterEntry         (сопоставление отдельно в каждой заявке на сезон, см. ниже)
Player 1─* MessengerAccount
Player 1─* Attendance *─1 Match
Match 1─1 MatchLineup → MatchApplication
```

## Жизненный цикл матча
Исходная гипотеза (дата известна с начала сезона, время — за 2–4 дня) **на сайтах лиг MVP не подтвердилась** (см. `data-sources.md`). Расписание лиги может публиковаться тремя способами:
- **A. Дата без времени, время позже.** Модель с `date_only` → `time_set`. Среди лиг MVP такой нет, но в других лигах может встретиться.
- **B. Матч появляется только когда назначен, сразу с временем** (АБЛ: швейцарская система, тур составляется во вторник). До появления матча сервис знает только «ожидаем игру в выходные».
- **C. Весь круг сразу с временем** (МЛБЛ). Время известно за недели, но может быть перенесено, предупреждение — за 4 дня.

Игры почти всегда по выходным.

**Правило запуска опроса** (общее для всех трёх способов, решение владельца 2026-10-18):
- **Все опросы недели запускаются одновременно в среду** перед игрой (по умолчанию 10:00 МСК, настраивается) — по всем матчам, время которых известно. Раньше среды опрос не запускается, даже если время известно заранее (МЛБЛ).
- Если время появилось позже среды — опрос запускается сразу, как только оно появилось.
- **Без известного времени опрос не запускается никогда.** Вместо этого капитан получает предупреждение: «время матча не назначено — свяжитесь с лигой». Первое предупреждение — в среду, в момент, когда должен был стартовать опрос, затем раз в сутки, пока время не появится или капитан не введёт его вручную.
- «Среда перед игрой» — ближайшая среда, не позже дня игры. Для игры в понедельник или вторник это среда предыдущей недели. ⚠ Редкий случай, уточнить при появлении.

Для АБЛ: матч появляется примерно во вторник, поэтому опрос обычно стартует в среду. Для МЛБЛ время известно заранее, и опрос всегда стартует в среду.

Статус матча: `scheduled` → `rescheduled` (сменилась дата) → `played` (есть счёт) | `cancelled` | `forfeit` (техническое поражение).

Статус времени (`time_status`):
| Значение | Смысл |
|---|---|
| `date_only` | Известна только дата (`match_date`), `start_at` пусто |
| `time_set` | Лига назначила время, `start_at` заполнено, есть зал. **Триггер запуска опроса** |
| `time_changed` | Время изменилось после назначения: уведомление команде, отметки сохраняются, но игроки получают просьбу подтвердить ответ |

## Подключение игрока к боту
- Игрок есть в чате команды, но **бот может писать ему в личку только после того, как игрок сам начал диалог** (так устроены и Telegram, и VK). Поэтому у игрока есть признак `dm_allowed`.
- Вход для игрока — кнопка-ссылка в чате команды («Подключиться» → Telegram: `t.me/<bot>?start=<payload>`; VK: `vk.me/<сообщество>?ref=…` → «Начать»). Подключение нужно только для личных сообщений; сопоставление с заявкой на сезон делает руководитель команды независимо от него (см. ниже).
- Игрокам без `dm_allowed` сигналы (напоминания, «нет в заявке на сезон») отправляются упоминанием в чате команды. Капитан видит в сводке, кто не подключён.
- **Список игроков ведёт сервис.** «Кто не ответил» считается по игрокам сервиса: подключившиеся, добавленные капитаном, найденные в заявках на сезон. В VK (бот — администратор беседы, ADR 0004) список дополняется участниками беседы, чтобы видеть и тех, кто ещё не подключился. В Telegram списка участников группы нет — только игроки сервиса.

## Сопоставление игрока с заявкой на сезон
Аккаунт VK игрока и строка в заявке на сезон — разные записи, их нужно связать. **Связь устанавливается отдельно для каждого выступления**: в разных лигах у игрока может быть разный номер, а сам он может быть заявлен в одной лиге и не заявлен в другой.

**Кто сопоставляет** (решение владельца 2026-10-18): только **руководители команды** — капитан, заместитель и действующий и. о. капитана (см. «Права капитана и их передача»). Сам игрок себя не сопоставляет.

**Как:**
- Бот только **предлагает** кандидата: фамилия + имя с учётом ё/е, регистра, латиницы (транслитерация), уменьшительных имён (Саша → Александр). VK отдаёт только имя и фамилию из профиля, отчества обычно нет — поэтому предложение всегда требует подтверждения.
- Руководитель команды получает в личке карточку: «Ivan Petrov (VK) → [Петров Иван, АБЛ, №12] [Выбрать из заявки на сезон] [Нет в заявке на сезон] [Не игрок команды]». «Выбрать из заявки» — кнопки со всеми строками заявки на сезон выступления (15–20 человек).
- **Кого сопоставлять:** всех участников беседы команды (бот — администратор и видит список, ADR 0004), не дожидаясь, пока игрок нажмёт «Начать». Новые участники беседы и новые строки заявки на сезон после синхронизации попадают в очередь «на сопоставление».
- **Вторая лига:** если игрок уже связан в одной лиге, бот предлагает связь в другой по ФИО + дате рождения из обеих заявок на сезон (две официальные записи — совпадение обычно однозначное). Однозначные предложения можно подтвердить пачкой: [Подтвердить все однозначные].
- **Конфликты** (два аккаунта VK на одну строку заявки, строка исчезла из заявки на сезон) — в очередь руководителям команды, бот сам не решает.
- Каждая связь хранит, кто и когда её подтвердил (`confirmed_by`). Связь можно исправить или удалить.
- Игрок может посмотреть свою привязку («Мои данные») и нажать [Это ошибка] — сообщение уходит руководителям команды.
- Капитан и заместитель в MVP заданы в конфигурации (VK ID) и сопоставляют себя сами.

## Права капитана и их передача
**Права капитана** (есть у капитана, заместителя и действующего и. о.):
- получать сводки за 24 ч и 2 ч и мгновенные изменения ответов;
- править заявку на игру (добавить/убрать игрока, номер), вводить время матча вручную, получать предупреждения «время не назначено» и «не хватает игроков»;
- сопоставлять игроков с заявками на сезон.

**Передача прав (и. о. капитана)** — решение владельца 2026-10-18:
- Передать может капитан или заместитель — **любому уже сопоставленному игроку** команды. Типичный случай: капитан и заместитель одновременно в отпуске.
- Передаются **все права капитана**.
- Срок: [3 дня] [7 дней] [14 дней] [До отмены] или до конкретной даты. По истечении права снимаются автоматически; и. о. и выдавший получают уведомление.
- Капитан и заместитель **свои права сохраняют** и могут отозвать передачу в любой момент. При передаче можно отметить [Не присылать мне сводки на это время] — чтобы не получать сообщения в отпуске.
- И. о. капитана **не может передавать права дальше** и не может отзывать права капитана и заместителя.
- Одновременно может быть несколько и. о. (например, по одному на каждую лигу) — сводки получают все.
- Беседа команды получает короткое сообщение: «До 30.10 обязанности капитана исполняет Иванов Пётр».
- Каждое действие руководителя (правка заявки на игру, сопоставление) хранит, кто его сделал.

Статусы игрока относительно выступления: `in_roster` (связан), `not_in_roster` (руководитель команды отметил «нет в заявке на сезон» — нужно дозаявить), `not_in_league` (руководитель отметил «не играет в этой лиге»: игрок команды, но в этом выступлении не играет и дозаявлять его не нужно), `unmatched` (ещё не сопоставлен).

## Правила
- Время матча хранится в UTC + таймзона лиги; показывается в таймзоне лиги.
- Все данные (кроме общих справочников лиг, турниров, команд в лигах, матчей) принадлежат конкретной команде сервиса (`tenant_id`). Изоляция обязательна и в MVP.
- **Проверка по заявке на сезон всегда идёт по выступлению того турнира, к которому относится матч.** Игрок, заявленный за Westchester в АБЛ, не считается заявленным за МИРЭА в МЛБЛ. Номер в заявке на игру берётся из заявки на сезон именно этой лиги.
- В сообщениях игрокам указывается, под каким названием команда играет в этом матче: «МИРЭА (МЛБЛ) — соперник …».
- Отметку участия игрок может менять до начала матча («Буду» ↔ «Не буду»). Повторное нажатие той же кнопки ничего не меняет — снять отметку совсем нельзя (решение владельца). Капитан правит заявку на игру в любой момент до начала матча.
- **Сводки капитану** — две на каждый матч:
  - **за 24 часа до игры**: черновик заявки на игру («номер + ФИО»), кто отказался, кто не ответил, кто не в заявке на сезон, хватает ли игроков. Капитан может внести правки;
  - **за 2 часа до игры**: обновлённая версия с учётом изменений после первой сводки (что поменялось — выделено). Это финальный список для подачи.
  - Если время матча назначено меньше чем за 24 часа до игры, первая сводка отправляется сразу после запуска опроса.
- Изменения отметок участия после первой сводки (за 24 ч) капитан получает сразу, отдельным коротким сообщением.
- Напоминание игрокам, которые не ответили, отправляется до первой сводки, чтобы капитан получил полную картину: за 30 ч до игры.
- **Размер заявки на игру: от 5 до 12 игроков.** Это настройка лиги (`min_players` = 5, `max_players` = 12 по умолчанию для АБЛ и МЛБЛ). Сервис не блокирует капитана, а предупреждает:
  - меньше 5 подтвердивших — тревога в сводках и при каждом отказе («не хватает N игроков»); стоит отдельно позвать не ответивших;
  - больше 12 — капитан выбирает, кого убрать; сервис перечисляет лишних и не пропускает финальный список, пока их не станет ≤ 12 (капитан всё равно может скопировать список, но с предупреждением).
- Заявка на сезон синхронизируется с сайта лиги регулярно (лиги дозаявляют игроков по ходу сезона). Дополнительные поля (дата рождения, позиция) забираются, если источник их отдаёт; набор полей зависит от адаптера.
- Игрок со статусом `not_in_roster` или `unmatched`:
  - может отметиться на матч, но в заявку на игру не попадает автоматически;
  - **сигнал капитану**: когда руководитель отмечает «нет в заявке на сезон» (остальным руководителям), при отметке `going` и в сводках капитану;
  - **сигнал игроку** — только при отметке `going` («Буду»); сама отметка руководителя «нет в заявке» игроку не отправляется;
  - сигнал снимается автоматически, когда игрок появился в заявке на сезон после синхронизации.
- Участник беседы, отмеченный «не игрок команды», если всё же отметился «Буду», показывается в составе на матч с ⚠️ («не сопоставлен с заявкой на сезон») и в заявку на игру автоматически не попадает. Его не прячут, чтобы капитан ничего не пропустил и решил сам.
- Игрок со статусом `not_in_league`: в заявку на игру не попадает, в сводках «нужно дозаявить» не показывается, при отметке руководителем уведомлений нет. Если всё же отметился `going` на матч этой лиги — сигнал игроку и капитану, как для `not_in_roster`.
- **Номер игрока** в заявке на игру берётся в таком порядке:
  1. из заявки на сезон этой лиги (АБЛ);
  2. если там номеров нет (МЛБЛ), — из последнего протокола матча этой лиги, где играл игрок; капитан или игрок подтверждает;
  3. иначе капитан вводит номер вручную.

  Номер хранится отдельно для каждого выступления.
- **Адрес зала:** если источник его не отдаёт (МЛБЛ), в анонсе указывается название зала из источника и, если задан, адрес лиги по умолчанию (в MVP все залы МЛБЛ — в одном здании). Справочник залов с адресами — после MVP.
- **Опрос участия запускается по правилу из раздела «Жизненный цикл матча»**: в среду и только при известном времени. Если времени нет, капитан получает предупреждение и связывается с лигой. Если время стало известно капитану раньше, чем появилось на сайте, капитан может ввести его вручную, и опрос запустится.
- **Заявку на игру составляет капитан.** Автоматически в неё попадают игроки с отметкой `going`, которые есть в заявке на сезон. Капитан может:
  - добавить игрока, который не ответил на опрос (и, в общем случае, любого игрока команды);
  - убрать игрока из заявки.

  Каждое ручное изменение фиксируется (`added_by_captain` / `removed_by_captain`). Проверка по заявке на сезон действует и для добавленных вручную.
- Перенос матча на другую дату (`rescheduled`) сбрасывает отметки участия с уведомлением, потому что новая дата может не подойти. Смена только времени в тот же день (`time_changed`) отметки не сбрасывает.
