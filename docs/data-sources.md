# Источники данных

Здесь — только проверенные сведения. Непроверенное помечать «⚠ не проверено».

## Что нужно получить
| Данные | Для чего | Частота обновления |
|---|---|---|
| Календарь по дням (сезон) | «Когда игра?», планирование | Раз в сутки (меняется редко) |
| Точное время и зал ближайшего матча | Триггер опроса, анонс | Неделя игры, пока матча нет или нет времени: каждые 1–2 часа днём (АБЛ — со вторника). После — раз в несколько часов до игры (ловим изменения) |
| Залы и адреса | Анонсы | Редко. В МЛБЛ адресов нет — справочник залов вручную |
| Турнирная таблица | Справка по сопернику | После каждого тура |
| Результаты матчей (счёт) | Справка, история встреч | После матча |
| Протоколы / boxscore (статистика игроков) | Лидеры соперника | После матча, если публикуются |
| **Заявка на сезон**: ФИО, номер; опционально дата рождения, позиция | Проверка игроков, номера для заявки на игру | Ежедневно + перед дедлайном заявки на игру |
| Регламент заявки на игру (срок подачи, минимум/максимум игроков) | Настройки лиги | Раз в сезон, вручную |

## Способы получения (в порядке предпочтения)
1. **Официальный API / JSON, который использует сам сайт** (часто виджеты лиг грузят данные отдельными запросами — проверять в DevTools → Network).
2. **Парсинг HTML** страниц расписания и таблицы.
3. **Экспорт** (календарь .ics, Excel/PDF), если лига его даёт.
4. **Ручной ввод** капитаном — всегда доступен как запасной вариант.

## Архитектурное требование: подключение по ссылке
В целевом решении капитан сам присылает ссылки на лигу и команду, поэтому лиги заранее не известны. Отсюда:
- Чтение данных строится через **адаптеры платформ**, а не через код под конкретную лигу. Один адаптер обслуживает все лиги на одной платформе (например, все сайты на одном движке или с одними и теми же виджетами статистики).
- Адаптер умеет: (1) по URL понять, его ли это платформа; (2) из ссылки на команду получить её ID в источнике; (3) отдать расписание, таблицу, результаты и заявку на сезон в общей модели из `domain.md`; (4) сообщить, какие дополнительные поля заявки на сезон (дата рождения, позиция) он умеет отдавать.
- Для неподдерживаемой платформы есть запасной вариант: ручной ввод расписания капитаном.
- В MVP ссылки задаются в конфигурации, но код сразу пишется через интерфейс адаптера, чтобы позже не переделывать.

Первые адаптеры определены лигами MVP: **`mtgame`** (АБЛ) и **`infobasket`** (МЛБЛ). Обе платформы обслуживают и другие лиги, так что для целевого решения это хороший старт. Какие ещё платформы распространены среди любительских лиг — ⚠ не исследовано.

| Канал | Статус | Что выяснить |
|---|---|---|
| Telegram | после MVP | Свойства Bot API — в ADR 0002 (⚠ не проверены); доступность в РФ и с VPS |
| VK | **MVP** (ADR 0003), целевой | Исследовано и проверено на тесте (`spikes/vk-probe/README.md`). Бота в беседу приглашает участник, не являющийся админом сообщества. См. ниже и `notes/sources/vk-bots.md` |
| Max | исследовать, **приоритет повышен** | Есть ли публичный API для ботов, условия доступа (юрлицо/верификация?), работа в групповых чатах, кнопки. Связь с переездом бесед VK в MAX (ошибка 993) |

### VK — выводы (по dev.vk.com, 2026-10-18, API 5.199)
- **Бот работает только от имени сообщества**: ключ сообщества с правами `messages`, `manage`. Боту на аккаунте пользователя право `messages` не выдаётся. → Команде нужно **создать сообщество**.
- **Беседа остаётся существующей.** В настройках сообщества включается «Разрешать добавлять сообщество в чаты», затем бот добавляется в беседу. Уровни доступа бота в беседе:

  | Уровень | Кто выдаёт | Что даёт |
  |---|---|---|
  | Только упоминания | сразу после добавления | писать в беседу; видеть упоминания бота и ответы на его сообщения |
  | Полный | любой админ беседы | + видеть все сообщения (нам не нужно) |
  | Администратор | создатель беседы или админ с правом назначать админов | + **список участников с именами** (`getConversationMembers`), объект беседы |

  **Зачем боту «Администратор»:**
  1. **Список «кто не ответил».** Без списка участников бот знает только тех, кто нажал кнопку или написал ему. Тех, кто молчит, он просто не видит.
  2. **Предложение подключиться.** По списку бот видит, кто в беседе ещё не нажал «Начать», и может упомянуть их.
  3. **Закрепление анонса**, скорее всего (ошибка 925 «You are not admin of this chat» у `messages.pin`). ⚠ не проверено.
  4. **Надёжность:** не документировано, приходят ли нажатия кнопок при уровне «только упоминания». ⚠ не проверено.

  **Без «Администратора» обойтись можно**, если список игроков ведёт сам сервис: игроки подключаются через «Начать», капитан добавляет остальных, плюс заявки на сезон с сайтов лиг. Тогда «кто не ответил» считается по этому списку, а не по участникам беседы. Минусы: капитану больше ручной работы, а закрепление и, возможно, кнопки не работают. Проверить на тестовой беседе.

  Также администратор беседы технически может читать её через API, но мы этого не используем: бот реагирует только на свои кнопки и прямые обращения.
- **События** — Bots Long Poll: не нужны публичный адрес и HTTPS, подходит для дешёвого VPS.
- **Опрос участия — inline callback-кнопки** «Буду / Не буду» под анонсом. Нажатие приходит с `user_id`, бот отвечает всплывающим уведомлением и редактирует анонс со счётчиком (`messages.edit`). Нативные опросы VK не подходят: `polls.*` работают только с ключом пользователя.
- **Личка: бот не может написать первым.** Игрок должен сам написать сообществу или разрешить сообщения. Схема: кнопка-ссылка `vk.me/<сообщество>?ref=…` в беседе → игрок нажимает «Начать». Это и согласие на сообщения, и удобный момент привязать игрока к заявке на сезон. Список разрешивших API не отдаёт, ведём сами. 🔶 Схема собрана из документированных частей, на практике не проверена.
  → **Напоминания и сигналы игроку в личку работают только для игроков, прошедших «Начать».** Для остальных — упоминание в беседе.
- **Лимиты:** 20 запросов/с на ключ сообщества, до 100 получателей в одном `messages.send`. **С 07.09.2026 — месячный лимит VK ID: 10 000 вызовов без верификации бизнес-профиля, 100 млн после.** ⚠ Касается ли он ключа сообщества — не подтверждено. Цитату нашёл агент, повторная проверка не удалась (страница правил отвечает 500). Оценка для MVP: одна команда, ~2 матча в неделю → порядка сотен вызовов в месяц, укладываемся. Для целевого решения на много команд понадобится верификация.
- **Переименование сообщества:** бот привязан к ID сообщества, а не к названию, поэтому переименование ему не мешает. По косвенным данным (ответ агента поддержки VK, сторонние источники), название обычного сообщества меняется в настройках; у верифицированных — через поддержку. Короткий адрес меняется без ограничений. ⚠ Официальную справку проверить не удалось. **Следствие:** ссылки «Подключиться» строить по ID сообщества, а не по короткому адресу, чтобы смена адреса их не ломала.
- **Библиотека:** vkbottle 4.11.0 (26.08.2026, API 5.199, Python 3.13).
- **Риски:**
  - новая ошибка `messages.send` **993 «Chat moved to MAX»**: похоже, беседы VK могут переезжать в MAX, и бот теряет доступ. Нужны обработка ошибки и уведомление капитана; MAX становится следующим каналом;
  - правила ботов запрещают рекламу в беседах (п. 7.1);
  - есть ограничения на хранение User ID (правила платформы, п. 2.1–2.2) — учесть в модели данных;
  - методы вне публичной документации VK будут ограничиваться — используем только документированные.
- **Проверено на тестовой беседе (2026-10-18, `spikes/vk-probe/README.md`):**
  - бота в беседу приглашает участник, **не являющийся админом сообщества** (у админа кнопки нет);
  - без доступа «Администратор»: анонс публикуется, **нажатия кнопок приходят**, бот видит только сообщения с упоминанием; список участников — ошибка 917, закрепление — ошибка 925;
  - с доступом «Администратор»: список участников и закрепление работают, но **бот получает все сообщения беседы**;
  - в личке: ссылка `vk.me/club<ID>?ref=…` → «Начать» даёт `message_allow` и `ref`; кнопки и `messages.edit` работают.
  - голосование от двух участников (веб и Android): оба нажатия учтены, имена в анонсе обновились; смена ответа переносит имя между списками.
- **Ещё не проверено:** через сколько времени `messages.edit` отказывает для старых сообщений; кнопки на iOS; событие о добавлении бота в беседу. Личку до «Начать» не проверяем — не нужна.

## Лиги

Подробности, эндпоинты и образцы ответов — в `notes/sources/<лига>/README.md`. Ниже — выжимка. Ключевые факты (расписание обеих команд) проверены выборочно 2026-10-18 повторным запросом к API.

### АБЛ — ablforpeople.com
- **Платформа:** MTGame (Angular SPA). Данные — из открытого JSON API `https://mtgame.ru/api/v1/` без авторизации. API недокументированный, эндпоинты найдены в коде сайта. Адаптер `mtgame`. ⚠ На MTGame, вероятно, работают и другие лиги — проверить при проектировании адаптера.
- **Наша команда:** «Westchester», `team_id` 279 (в базе с опечаткой «Whestchester»), турнир 4145 «Шелепиха» сезона 231, `tournament_team_id` 31988. Сопоставлять по ID, не по названию.
- **Расписание:** `tournament/{id}/games/?team_id=…`. Время в UTC. Зал и **адрес** есть в игре (`tournament_court`).
- **Время матча:** турнир по швейцарской системе, поэтому **матч следующего тура появляется в API только когда тур составлен, и сразу с точным временем**. Матчей «дата без времени» нет. По регламенту время согласуется в капитанском чате с понедельника 12:00 до вторника 18:00. Значит, матч появляется в API примерно со вторника (⚠ точный момент не проверен). До этого сервис знает только «ожидаем игру в выходные».
- **Таблица:** `tournament/{id}/teams/`. **Протоколы и статистика игроков:** есть (`tournament_basketball_game/{id}/user_statistic/`, `basketball_statistic/?group_by=tournament_team_user`). Лидеры (`basketball_statistic_leaders`) вернули ошибку 500.
- **Заявка на сезон:** `tournament_team/{id}/users/`. Есть **номер**, ФИО, фото; дата рождения — у всех; амплуа — у большинства; рост.
- **Регламент:** заявка на игру — отметка игроков на сайте под логином капитана **не позднее чем за 1 ч** до игры; на игру до 12 (`max_game_users`), на площадке минимум 4; в заявке на сезон 5–25.
- **Ограничения:** robots.txt не запрещает; Cloudflare, капчи и лимитов частоты не обнаружено. RSS и iCal нет.

### МЛБЛ — moscow.ilovebasket.ru
- **Название на сайте:** «МЛБЛ-Москва», Чемпионат Москвы по баскетболу среди любительских команд.
- **Платформа:** свой сайт (ASP.NET MVC + AngularJS), данные — из открытого JSON API **Infobasket** `https://reg.infobasket.su` без авторизации, недокументированный. Адаптер `infobasket`. Тот же движок и API у других городов ilovebasket (проверены ekb, nsk, samara, krsk; vlad устроен иначе); Infobasket используют и другие лиги.
- **Наша команда:** «МИРЭА», TeamID 9056, дивизион «Лига развития (3)» (CompID 142706), этап 150011, сезон 150000.
- **Расписание:** `Widget/TeamGames/{team}?compId={сезон}`. Есть флаг `HasTime` и время по UTC и Москве. Зал — **только название** («ТМ. 4 зал»), **адресов нет нигде**.
- **Время матча:** **весь круг опубликован заранее, сразу с временем** (у МИРЭА 10 матчей до 21.11, у всех `HasTime: true`; по Москве — 773 из 773). По регламенту оргкомитет может переносить игры, предупредив за 4 дня, поэтому календарь надо регулярно перечитывать и сравнивать. Матч может ещё не быть в календаре (например, игра с «Московский банк» не найдена).
- **Таблица:** `Widget/CompTeamResults/{этап}`. **Протокол, boxscore, play-by-play:** `Widget/GetOnline/{game}` (протокол появляется с задержкой до суток). **Превью матча со статистикой обеих команд:** `Comp/GetTeamStatsForPreview/{game}`.
- **Заявка на сезон:** `Widget/TeamRoster/{team}?compId=…`. ФИО с отчеством, дата рождения, позиция, рост, вес, фото, капитан. **Номеров нет**, они есть только в протоколах матчей.
- **Регламент:** на игру 5–12 игроков; заявка на игру подаётся на `org2.ilovebasket.ru` (под логином) **не позднее чем за 15 минут** до начала.
- **Ограничения:** robots.txt нет (404); Cloudflare, капчи и лимитов не обнаружено. Ключ матча — `GameID` (`GameNumber` не уникален). Город может держать в меню прошлый сезон.

### Сравнение и выводы
| | АБЛ (MTGame) | МЛБЛ (Infobasket) |
|---|---|---|
| Когда известно время | Со вторника недели игры, матч появляется сразу с временем | За недели, весь круг заранее |
| Адрес зала | Есть | Нет — ведём справочник залов вручную |
| Номера в заявке на сезон | Есть | Нет — берём из последних протоколов, капитан подтверждает |
| ДР / позиция | Есть / почти у всех | Есть / есть |
| Срок подачи заявки на игру | За 1 ч до игры | За 15 мин до игры |

- **Модель «дата с начала сезона, время за 2–4 дня» не подтвердилась ни в одной лиге.** В АБЛ матча нет вовсе, пока не составлен тур, а в МЛБЛ время известно сразу. Правило запуска опроса нужно обобщить, см. `domain.md`.
- Сводка капитану за 2 ч укладывается в оба срока подачи (1 ч и 15 мин).
- **Персональные данные.** Оба API публично отдают даты рождения. Забираем только поля, которые реально нужны, и не храним лишнего (152-ФЗ).
- Оба API недокументированные: нужны контрактные тесты на сохранённых образцах и громкое падение при смене формата.
