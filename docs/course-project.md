# Basket Assist — бот-помощник любительской баскетбольной команды

_Выпускная работа по курсу Claude Code. Статус: этапы M0–M4 готовы, бот работает на VPS (M5) в тестовой беседе; впереди пилот в беседе команды (M6). Документ обновляется по ходу проекта._

## Проблема
Любительская команда живёт сразу в нескольких местах. Расписание — на сайтах лиг (у нашей команды их две, и в каждой она называется по-своему). Статистика соперника — там же, но искать её неудобно. Состав на игру собирается вручную опросом в общем чате.

В итоге:
- игроки не всегда знают, когда и с кем следующая игра и где зал;
- капитан каждую неделю вручную создаёт опрос, пересчитывает ответы, напоминает молчащим и переписывает номера и ФИО в заявку на игру;
- легко заявить игрока, которого нет в заявке на сезон, — это выясняется перед самой игрой;
- переносы матчей и смена времени замечаются с опозданием.

Это рутина, которая повторяется каждую неделю сезона, отнимает время капитана и приводит к ошибкам в заявке на игру.

## Пользователь
Игроки и капитан любительской баскетбольной команды в России, которая играет в одной или нескольких любительских лигах:
- **игрок** — хочет узнать ближайшую игру и отметиться в один тап;
- **капитан и его заместитель** — хотят получить готовую, проверенную заявку на игру и вовремя узнавать об изменениях.

Первая команда — наша: «Westchester» в лиге АБЛ и «МИРЭА» в лиге МЛБЛ-Москва. В перспективе сервис доступен любой любительской команде.

## Основная функция
**Вход:**
- ссылки на сайты лиг и страницы команды (в MVP заданы в конфигурации);
- данные лиг из открытых JSON API: расписание, время и зал матча, турнирная таблица, протоколы, заявка на сезон (АБЛ — платформа MTGame, МЛБЛ — Infobasket);
- ответы игроков в беседе VK (кнопки «Буду / Не буду»; в анонсе видно, кто как ответил);
- правки капитана: добавить или убрать игрока, ввести время матча вручную.

**Что делает сервис:**
1. Регулярно синхронизирует расписание, таблицу и заявки на сезон с сайтов лиг и замечает изменения (перенос, смена времени, дозаявка игроков).
2. В среду перед игрой публикует в беседе команды анонс матча и опрос участия, если время матча известно. Если времени нет — предупреждает капитана, что нужно связаться с лигой.
3. Напоминает в личке игрокам, которые не ответили.
4. Проверяет каждого игрока по заявке на сезон именно той лиги, где проходит матч, и сигнализирует игроку и капитану, если игрока нужно дозаявить.
5. Формирует черновик заявки на игру («номер + ФИО», от 5 до 12 игроков) и присылает капитану сводки за 24 часа и за 2 часа до игры. Изменения ответов после первой сводки приходят капитану сразу.
6. По запросу выдаёт справку по сопернику: место в таблице, результаты, средние очки, история встреч.

**Инструменты:** бот сообщества VK (Bots Long Poll, inline callback-кнопки), адаптеры к API лиг, планировщик задач, локальная база данных.

## Формат результата
- **Игрок** получает в VK анонс матча (дата, время, зал, соперник, лига), опрос в один тап, напоминания и сигналы о заявке на сезон, а по запросу — ближайшие игры и справку по сопернику.
- **Капитан** получает в личке готовую заявку на игру — список «номер + ФИО», который можно скопировать и подать на сайте лиги. Там же — кто отказался, кто не ответил, кто не в заявке на сезон и хватает ли игроков.

## Минимальный функционал (MVP)
**В первой версии:**
- одна команда (наша) в двух лигах — АБЛ и МЛБЛ-Москва — с разными названиями и заявками на сезон;
- канал — VK: беседа команды и личные сообщения;
- синхронизация расписания, таблицы и заявок на сезон через API лиг, ручной ввод времени капитаном;
- привязка игроков VK к заявкам на сезон и сигналы «нет в заявке на сезон»;
- опрос участия, напоминания, сводки капитану за 24 ч и 2 ч, правка заявки на игру капитаном;
- базовая справка по сопернику.

**Планируется после MVP:**
- подключение любой команды: капитан сам даёт ссылки на лигу и команду;
- Telegram и мессенджер MAX как альтернативные каналы на выбор команды;
- новые платформы лиг (новые адаптеры);
- индивидуальная статистика игроков и более подробный скаутинг соперника;
- справочник залов с адресами;
- возможная монетизация (сейчас сервис бесплатный).

## Технологии
- **Язык:** Python 3.13.
- **Библиотеки** (план, фиксируется в ADR): vkbottle — бот VK; httpx — запросы к API лиг; APScheduler — планировщик; SQLite — хранение в MVP; pytest — тесты, в том числе на сохранённых образцах ответов API лиг.
- **Внешние API и форматы:**
  - VK API 5.199 (Bots Long Poll, `messages.*`), ответы в JSON;
  - JSON API лиг: MTGame (`mtgame.ru/api/v1`) и Infobasket (`reg.infobasket.su`);
  - сообщения пользователям — текст с inline-клавиатурами VK.
- **Инфраструктура:** VPS RUVDS (Debian 13) в российском дата-центре (152-ФЗ), минимальный тариф, один процесс, бэкап базы по расписанию.
- **Архитектура:** адаптеры платформ лиг (`PlatformAdapter`) и мессенджеров (`ChannelAdapter`) отделены от бизнес-логики; данные изолированы по команде сервиса (мультитенантность).

### Как используется Claude Code
- `CLAUDE.md` — системные инструкции проекта: домен, ограничения, правила работы, текущий статус;
- документация как источник истины: `docs/vision.md`, `docs/domain.md` (глоссарий), `docs/data-sources.md`, `docs/open-questions.md`, ADR в `docs/decisions/`;
- параллельные субагенты для исследований: API ботов VK, сайты двух лиг, сравнение VPS. Ключевые выводы проверяются выборочными повторными запросами;
- проверка гипотез на практике до кода: тест бота VK на тестовой беседе (через управление браузером) выявил блокер «бота нельзя добавить в беседу»; канал временно сменили на Telegram (ADR 0002), но проверка с другого аккаунта показала, что пригласить бота может участник, не являющийся админом сообщества, — и вернулись к VK (ADR 0003);
- проверочные скрипты (`spikes/`) — для проверки гипотез до написания кода сервиса;
- далее: разработка MVP с тестами, ревью кода (`/code-review`), развёртывание;
- по завершении MVP — скилл проекта для Claude Code и публикация репозитория на GitHub.

## Демонстрация на защите (черновик)
1. Проблема: как сбор состава выглядит сейчас — ручной опрос в чате.
2. Живая демонстрация в тестовой беседе VK: анонс → нажатия кнопок → игрок не в заявке на сезон → сигнал → сводка капитану → готовая заявка на игру.
3. Данные лиг: синхронизация реального расписания Westchester и МИРЭА.
4. Как проект строился с Claude Code: инструкции, исследования субагентами, ADR, тесты.
5. Планы развития.
